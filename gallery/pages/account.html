Step-up

stepUp(action, options) runs a write that needs a recent sign-in. When the server asks for one, "Confirm it is you" names the action and offers only what the account holds and the app mounts, then runs the action once more. Cancel and Escape close it with no error and give focus back to the button.

Confirm it is you

A password, a passkey and single sign-on. Type "wrong" for the wrong password's field error, or "limit" for a rate limit; any other password confirms. The passkey runs out of time once, then confirms.

With an authenticator app

An account with an authenticator app, on an app that offers no password at step-up: the code field first, with numeric keys. Type 111111 for a wrong code, 222222 for one already used, 333333 for a locked app; any other six digits confirm.

Only a passkey

Account and security

mountSecurity(region, options) fills the signed-in person's own screen: who is signed in, the profile, then the sign-in methods with each one's state as a .cp-state and its actions, the passkeys, the sessions and the API keys. The cards here leave out the parts another card shows. Here it sits inside a settings part, its sections at level: 3. A write that needs a recent sign-in asks "Confirm it is you" first.

The whole screen

Profile, then every method: a password, two passkeys, an authenticator app with its recovery code, and single sign-on; then Sessions, API keys and, for an admin, the security log of their own entries, as the cards below them show. Type "wrong" as the current password for its field error, or a new password under 15 characters. In a code field, 111111 is a wrong code and 222222 one already used. Remove password asks to confirm it is you first. Rename edits the name in its cell: Enter saves, Escape puts it back.

The kind, the account and the order are filters, held in the address with the page, so Back returns to a page and a page opens in a new tab. Newer and Older page by the entries themselves, since entries keep arriving. Account and security shows the same view, for an admin, under its own sections.

Users

mountUsers(region, options) is the admin's list of the app's people: each one's role, with "from the identity provider" when the role follows it, the Owner badge, whether they can sign in, their ways in, a live temporary password and dormant local sign-in among them, and the keys that reached them. Each row's actions sit in its menu, and the list is read again after every change, so what a row says is the server's. Add user and Invite sit above it, the waiting invites and every account's API keys below.

Access settings

mountAccessSettings(region, options) is the owner's choice of how single sign-on sits beside local sign-in. Choosing a mode asks the server, after a recent sign-in, what it would change, and shows that before Apply; a state the owner must fix first shows in its place, with no Apply. It draws nothing for an admin who is not an owner, or in an app with one account.

Choosing a mode

Single sign-on only would leave 3 people who are not linked yet unable to sign in, make 5 people's own sign-in dormant and withdraw 2 temporary passwords. For linked accounts changes nobody's sign-in here. Apply makes the change; choosing Alongside again asks nothing.

Something to fix first

Here single sign-on is not set up, so any stricter mode says "Set up single sign-on first." in place of its changes. The server answers the same way for an owner with no password or passkey of their own, and while sign-ups are on.

Over plain HTTP

The server checks and changes the mode only over HTTPS, so the choice is held with "Needs HTTPS." and the way to the HTTPS address.

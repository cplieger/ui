Account screens

The shared screens of an app built on @cplieger/access, from @cplieger/ui/account, each running here on a fake client. A screen fills the element the app gives it, takes the app's words for any answer, and shows a method only while the app mounts it and the server has it on.

Sign-in

mountSignIn(panel, options) fills the gate page's panel: the password form, then a passkey and single sign-on under a rule, then the recovery hint in the panel's foot. The line under the panel is the app's own.

Help for this screen

Every method on, after a session ended. Type the password "wrong" for a refused sign-in, "busy" for a busy server, "limit" for a rate limit, or a username with a space. Each press of Sign in with a passkey answers the next outcome: ran out of time, not registered here, closed prompt, then signed in.

Setup

mountSetup(region, options) creates the first account: the setup token when the app asks for one, a username and a password, or a passkey under a rule. It fills the gate page's panel, or a step of the app's own setup with no heading of its own. After a password setup the app may offer a passkey.

The setup page

RRelease tracker
The token field with the app's help naming its command, then the passkey under a rule. Type the token "wrong" for a token that does not work, the password "common", "breached" or "short" for each refused password, "limit" for a rate limit, or a username with a space. A password setup that works offers a passkey next.

Step-up

stepUp(action, options) runs a write that needs a recent sign-in. When the server asks for one, "Confirm it is you" names the action and offers only what the account holds and the app mounts, then runs the action once more. Cancel and Escape close it with no error and give focus back to the button.

Confirm it is you

A password, a passkey and single sign-on. Type "wrong" for the wrong password's field error, or "limit" for a rate limit; any other password confirms. The passkey runs out of time once, then confirms.

With an authenticator app

An account with an authenticator app, on an app that offers no password at step-up: the code field first, with numeric keys. Type 111111 for a wrong code, 222222 for one already used, 333333 for a locked app; any other six digits confirm.

Only a passkey

No password and no single sign-on: the passkey is the one method and the primary, with focus on it.

Sign in again over plain HTTP

A plain session cannot step up, so the server asks for a fresh sign-in: the sign-in form with the username fixed, then the action runs once more.

QR code

qrCode(text) from @cplieger/ui/qr draws a text as a QR code in the page, so the secret in an authenticator link never leaves it. The key beside it, in groups of four, is the way in for a person who cannot scan.

An authenticator link

JBSW Y3DP EHPK 3PXP JBSW Y3DP EHPK 3PXP
A version 6 code at level M, dark on light in both themes and under forced colours, hidden from assistive technology since the key beside it says the same.
